# Phase 2 Plan 01: Database Migration + Stage API

## Goal

Add leads.stage_id FK and create pipeline stages CRUD API with service layer.

## Background

Phase 1 created `pipeline_stages` table seeded with odontologia defaults. This plan adds leads columns (stage_id, source_type, score, converted_at, converted_to_patient_id) and creates the full stage CRUD service + API routes.

## Context

@supabase/migrations/20260424000002_create_pipeline_stages.sql -- existing pipeline_stages table
@src/services/leads/leads.service.ts -- existing leads service with scoring functions
@src/lib/supabase/typed.ts -- createTypedClient() for RLS-enforced queries
@src/lib/supabase/server.ts -- getUserProfile() for auth

## Tasks

### Task 1: Create leads pipeline columns migration

<action>
Create `supabase/migrations/20260425000001_add_leads_pipeline_columns.sql`:
- ALTER TABLE leads ADD COLUMN stage_id UUID REFERENCES pipeline_stages(id)
- ALTER TABLE leads ADD COLUMN source_type TEXT CHECK (whatsapp,manual,referral,website,paid_media) DEFAULT 'manual'
- ALTER TABLE leads ADD COLUMN score DECIMAL(5,2) DEFAULT 0
- ALTER TABLE leads ADD COLUMN converted_at TIMESTAMPTZ
- ALTER TABLE leads ADD COLUMN converted_to_patient_id UUID
- CREATE INDEX idx_leads_stage_id ON leads(stage_id)
- CREATE INDEX idx_leads_source_type ON leads(source_type)
- CREATE INDEX idx_leads_score ON leads(score)

Add database trigger for automatic score recalculation (MEDIUM-1):
- CREATE OR REPLACE FUNCTION trigger_auto_score_lead() RETURNS TRIGGER AS $$
  BEGIN
    NEW.score = calculate_lead_score(NEW.id);
    RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;
- CREATE TRIGGER trg_lead_score_on_insert AFTER INSERT ON leads FOR EACH ROW EXECUTE FUNCTION trigger_auto_score_lead();
- CREATE TRIGGER trg_lead_score_on_update AFTER UPDATE ON leads FOR EACH ROW WHEN (OLD.last_contact IS DISTINCT FROM NEW.last_contact OR OLD.source IS DISTINCT FROM NEW.source) EXECUTE FUNCTION trigger_auto_score_lead();

Add a default stage constraint:
- INSERT default_stage as the first stage (sort_order = 0) with is_default = true
- Create partial migration to set leads.stage_id to default_stage when stage_id is NULL
</action>

- SELECT triggername FROM information_schema.triggers WHERE triggername LIKE '%score%'

### Task 3: Create pipeline stages API routes

<action>
Create three route files:

1. `src/app/api/pipeline/stages/route.ts`:
   - GET: list stages for clinic (getUserProfile().clinic_id), filter out is_default from response

2. `src/app/api/pipeline/stages/[id]/route.ts`:
   - PATCH: update stage (name, color, sort_order). Return 403 if trying to update is_default stage
   - DELETE: delete stage. If leads exist, move them to default stage first, then delete. Return 400 if leads exist and no default stage.

3. `src/app/api/pipeline/stages/reorder/route.ts`:
   - PATCH: bulk reorder stages [{id, sort_order}, ...]. Validate all IDs belong to user's clinic.

## Threat Model

| Boundary | Description |
|----------|-------------|
| client -> API | Unauthenticated requests blocked via getUserProfile() |

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-02-01 | Spoofing | Stage API | mitigate | getUserProfile() enforces clinic ownership on all operations |
| T-02-02 | Tampering | Stage reorder | mitigate | Array.isArray check + clinic ownership validation before processing |
| T-02-03 | Denial | Stage delete | mitigate | Leads moved to default stage before delete (no orphan leads) |
| T-02-04 | Information | Score trigger | mitigate | Trigger only recalculates score for same lead, no cross-lead access |

## Success Criteria

1. Migration adds stage_id, source_type, score, converted_at, converted_to_patient_id to leads table
2. Database trigger auto-recalculates score when leads are inserted or when last_contact/source changes
3. Default stage (is_default=true) exists for every clinic and cannot be deleted while leads exist
4. deletePipelineStage moves leads to default stage before deleting
5. reorderPipelineStages validates all stage IDs belong to the user's clinic
6. stages.service.ts exports all 7 functions with createTypedClient() for RLS
7. GET /api/pipeline/stages returns stages ordered by sort_order (is_default filtered out)
8. POST /api/pipeline/stages creates new stage with auto-assigned sort_order
9. DELETE /api/pipeline/stages/[id] moves leads to default stage and deletes
10. PATCH /api/pipeline/stages/reorder accepts array of {id, sort_order} with clinic validation
