| Dominant (60%) | `hsl(var(--background))` — #FFFFFF light / #0F172A dark | Page backgrounds |
| Secondary (30%) | `hsl(var(--card))` — #FFFFFF light / #1E293B dark | Cards, panels, detail sections |

### Pattern 2: Financial Summary Tab Content
- **Source:** `src/components/contacts/contact-financial-tab.tsx` (new)
- **Layout:** Vertical stack of `TreatmentPlanCard` components, each showing:
  - Plan name + status badge
  - Progress bar (sessions done/total with color thresholds)

  - Link to budget detail

### Pattern 3: Payment Recording Dialog
- **Source:** `src/components/contacts/payment-recorder-dialog.tsx` (new)
- **Fields:** amount (currency input), date (date picker), method (select: Pix, credit, debit, cash, boleto), notes (optional textarea)
- **Validation:** amount must not exceed remaining balance (from RESEARCH.md Pitfall 3 prevention)

### Pattern 4: Budget Document Layout
- **Source:** `src/components/contacts/budget-detail-panel.tsx` (new)
- **Layout:** Two-column on desktop (items left, installments right)
- **Items table:** procedure name, quantity, unit price, total
- **Installments table:** amount, due date, paid status (with pay button for unpaid)

## Interaction Contracts

### Treatment Plan Card Interactions
| Interaction | Behavior |
|-------------|----------|
| Click on card | Expand to show sub-treatments |
| Progress bar fill | Color based on thresholds (red <30%, amber 30-70%, green >70%) |
| Status badge | `draft` (gray), `active` (blue), `completed` (green), `cancelled` (red) |

### Payment Recording Flow
1. User clicks `Registrar Pagamento` CTA on installment or budget
2. Dialog opens with: amount (pre-filled with installment amount), date (today), method dropdown, notes
3. User fills form and submits
4. On success: installments list updates, budget status may change to `accepted` (D-11), sessions auto-complete (D-09)
5. On error: show error toast, form stays open

### Budget Accept/Reject Flow
- `Enviar Orcamento` — sends to patient (existing endpoint)
- `Aceitar` / `Rejeitar` — patient decision buttons (existing endpoints)
- Status updates: `pending` → `accepted` or `rejected`
