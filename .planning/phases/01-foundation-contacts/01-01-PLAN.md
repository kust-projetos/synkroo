**Migration 02 -- create_pipeline_stages.sql:**
Per D2 and RESEARCH Pattern 6:
```sql
CREATE TABLE IF NOT EXISTS pipeline_stages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Migration SQL -> Database | SQL must be idempotent, no destructive drops without safety checks |
| New tables -> RLS | Every new table has clinic_id denormalized and RLS policy using get_user_clinic_id() |
| Consents trigger -> audit_logs | Trigger writes with SECURITY DEFINER, must not bypass RLS on audit_logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | New CRM tables without RLS | mitigate | Every table gets ENABLE ROW LEVEL SECURITY + policy using (SELECT get_user_clinic_id()) |
| T-01-02 | Information Disclosure | Cross-clinic data leak via custom_field_values | mitigate | clinic_id denormalized in custom_field_values, RLS checks clinic_id directly (avoids nested subqueries through definitions table) |
| T-01-03 | Tampering | Consent bypass via direct DB manipulation | mitigate | Audit trigger (SECURITY DEFINER) logs all consent changes to audit_logs with old/new values |
| T-01-04 | Repudiation | Consent changes without audit trail | mitigate | trg_consent_audit trigger fires on INSERT/UPDATE/DELETE, immutable audit_logs record |
| T-01-05 | Information Disclosure | leads.stage_id migration leaving orphaned leads | accept | Validation query checks for NULL stage_id, expand-contract pattern keeps status column for rollback |
</threat_model>
