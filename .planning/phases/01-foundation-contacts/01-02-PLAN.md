**src/services/contacts/contacts.service.ts:**
Follow the existing service pattern (import `createTypedClient` from `@/lib/supabase/typed`). All functions take `clinicId: string` as first param.

Key functions:

1. `searchContacts(clinicId, params: ContactListParams)`:
   - If type is 'patient' or 'all': query patients table with ILIKE search on name/phone/email/cpf
   - If type is 'lead' or 'all': query leads table with same ILIKE pattern
   - Tag filter: use Supabase `.contains('tags', tags)` (GIN index supports this)
   - Status filter: `.eq('status', status)`
   - Map results to unified Contact type with `type: 'patient'` or `type: 'lead'`
   - For 'all': run both queries in parallel with `Promise.all`, merge and sort by `updated_at DESC`
   - Paginate with `.range((page-1)*limit, page*limit-1)`

2. `getContactById(clinicId, contactId, contactType)`:
   - If contactType is 'patient': query patients by id + clinic_id
   - If 'lead': query leads by id + clinic_id (include stage_id via join to pipeline_stages for stage name/color)
   - Return unified Contact or null

3. `createContact(clinicId, input: ContactCreateInput)`:
   - Validate with Zod schema (inline or separate): name required, phone required, type must be 'patient'|'lead'
   - If type='patient': insert into patients table
   - If type='lead': insert into leads table with stage_id set to the default 'new' stage for the clinic (query pipeline_stages WHERE clinic_id AND system_key='new')
   - Return created Contact

4. `updateContact(clinicId, contactId, contactType, input: ContactUpdateInput)`:
   - Update the appropriate table (patients or leads) where id=contactId AND clinic_id=clinicId
   - Return updated Contact

5. `archiveContact(clinicId, contactId, contactType)`:
   - Set status to 'archived' on the appropriate table

6. `getContactNotes(clinicId, contactId, contactType)`:
   - For leads: query lead_activities WHERE lead_id AND activity_type='note', return as ContactNote[]
   - For patients: query patient_observations WHERE patient_id AND clinic_id, order by created_at DESC. Map to ContactNote shape: `{ id, contact_id: patient_id, contact_type: 'patient', content, created_at, created_by }`. This uses the new patient_observations table instead of the old patients.notes text field.

7. `addContactNote(clinicId, contactId, contactType, content: string)`:
   - For leads: insert into lead_activities with activity_type='note'
   - For patients: insert into patient_observations with patient_id=contactId, clinic_id=clinicId, content=content, created_by=current user id. This writes to the patient_observations table (created in Plan 01 migration 07) for proper individual notes with attribution and pagination.

```typescript
export function useContacts(params?: Record<string, string>) {
  const query = new URLSearchParams(params || {}).toString()
  return useQuery({
    queryKey: [queryKeys.contacts, params],
    queryFn: async () => { const res = await fetch(`/api/contacts?${query}`); if (!res.ok) throw new Error('Failed to fetch contacts'); return res.json(); }
  })
}

export function useContact(id: string, type: string) {
  return useQuery({
    queryKey: [queryKeys.contacts, id, type],
    queryFn: async () => { const res = await fetch(`/api/contacts/${id}?type=${type}`); if (!res.ok) throw new Error('Failed to fetch contact'); return res.json(); },
    enabled: !!id && !!type,
  })
}

export function useContactNotes(id: string, type: string) {
  return useQuery({
    queryKey: [queryKeys.contacts, id, 'notes', type],
    queryFn: async () => { const res = await fetch(`/api/contacts/${id}/notes?type=${type}`); if (!res.ok) throw new Error('Failed to fetch notes'); return res.json(); },
    enabled: !!id && !!type,
  })
}
```
