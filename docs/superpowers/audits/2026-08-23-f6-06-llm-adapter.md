## Resumo

- **Requisito F6.06:** ADR escolhe LLM provider, embedding model e dimensão produzida pelo modelo antes de ingestão. Criar LLM adapter real com comportamento estrito de fail-closed (falhar fechado sem provider/bridge/DB).
- **Implementações:**
  1. **ADR Ratificada (`docs/adr/adr-llm-embedding.md` & `ADR-INDEX.md`):**
     - LLM Provider Primário: **MiniMax** (`MiniMax-M2.7`) via OpenAI-compatible endpoint.
     - Provedores Fallback: **OpenAI** (`gpt-4o-mini`, `gpt-4o`) e **OpenRouter** (`anthropic/claude-3.5-sonnet`).
     - Modelo de Embedding: **`text-embedding-3-small`**.
     - Dimensão Vetorial Fixa: **`1536`** integrada com `pgvector` (`vector(1536)`).
  2. **Camada Adapter (`src/lib/llm/`):**
     - [`src/lib/llm/types.ts`](file:///D:/projetos/synkroo/src/lib/llm/types.ts): Definições de tipos, contratos, mensagens, function calling / tool definitions e constantes (`EMBEDDING_DIMENSIONS = 1536`).
     - [`src/lib/llm/errors.ts`](file:///D:/projetos/synkroo/src/lib/llm/errors.ts): Hierarquia `LlmError` com códigos estruturados (`missing_api_key`, `unauthorized`, `rate_limited`, `timeout`, `provider_down`, `invalid_response`) e sanitização/redação ativa de segredos.
     - [`src/lib/llm/providers/base.ts`](file:///D:/projetos/synkroo/src/lib/llm/providers/base.ts): `BaseLlmProvider` com validação fail-closed, retentativas seguras apenas para erros transitórios (429, 5xx, network), timeout budget e parsing resiliente de tool calls.
     - [`src/lib/llm/providers/minimax.ts`](file:///D:/projetos/synkroo/src/lib/llm/providers/minimax.ts): Implementação MiniMax.
     - [`src/lib/llm/providers/openai.ts`](file:///D:/projetos/synkroo/src/lib/llm/providers/openai.ts): Implementação OpenAI.
     - [`src/lib/llm/providers/openrouter.ts`](file:///D:/projetos/synkroo/src/lib/llm/providers/openrouter.ts): Implementação OpenRouter com headers de identificação.
     - [`src/lib/llm/factory.ts`](file:///D:/projetos/synkroo/src/lib/llm/factory.ts): `createLlmProvider` e `getLlmProvider` com resolução via ambiente (`LLM_PROVIDER`, `MINIMAX_API_KEY`, etc.).
  3. **Testes de Contrato (`src/lib/llm/__tests__/llm-adapter.test.ts`):**
     - 14 testes unitários e de contrato cobrindo:
       - Resolução de factory e default providers.
       - Fail-closed com chave ausente (`missing_api_key`).
       - Fail-closed com provedor fora do ar / erro de rede (`provider_down`).
       - Tratamento de rate limit (`rate_limited` HTTP 429).
       - Tratamento de 401 Unauthorized sem retentativas indevidas.
       - Tratamento de resposta JSON corrompida (`invalid_response`).
       - Timeout budget / abort signal (`timeout`).
       - Redação de tokens e chaves de API em mensagens e logs de erro.
       - Parsing de function calling / tool calls no padrão OpenAI.
