## DB constraint — overbooking
- **Migration:** `src/lib/db/migrations/0001_dapper_overlap.sql:48-66` — `CREATE EXTENSION btree_gist` + `ALTER TABLE appointments ADD CONSTRAINT appointments_no_overlap EXCLUDE USING gist (clinic_id WITH =, dentist_id WITH =, int8range(epoch AT TIME ZONE 'UTC') WITH &&) WHERE (status NOT IN ('cancelled','no_show') AND deleted_at IS NULL)`
- **Reprodutibilidade:** `scheduling-service.ts:30-35,50-53` mapeia `err.cause.code === '23P01'` → `ActionError('conflict')`; `conflict-detection.test.ts` cobre 3 casos de overlap + adjacente + dentist null + snake_case + auth.
- **Integração prova:** `availability.integration.test.ts` insere duas linhas com mesmo `clinic_id`+`dentist_id`+`int8range` sobreposto e assert `rejects.toThrow(/23P01|exclusion|overlap/i)`; adjacente `10:00` após `09:00-10:00` passa; cross-clinic e cross-dentist passam; `cancelled` libera; concorrência `Promise.allSettled` 2 inserts → 1 fulfilled 1 rejected.

## Timezone por clínica
- **Coluna:** `clinics.timezone text NOT NULL DEFAULT 'America/Sao_Paulo'` — migration idempotente, backfill legacy `settings.timezone`.
- **Resolução:** `resolveClinicTimezone({timezone, settings})` prioriza coluna, depois `settings.timezone` (objeto ou JSON string), depois default. `getClinicTimezone(clinicId)` faz `SELECT timezone, settings FROM clinics WHERE id = ?` via Drizzle, fallback `America/Sao_Paulo` se DB indisponível (unit tests).
- **Cálculo:** `zonedTimeToUtc(date, time, tz)` iterativo com `Intl.DateTimeFormat('en-CA', {timeZone})` → converte wall time local para UTC correto mesmo com DST e offset +14. `getDayOfWeekInTimezone` usa `zonedTimeToUtc(date,'12:00',tz)` + `Intl` weekday short → 0-6. `getDayRangeUtc` usa `zonedTimeToUtc(date,'00:00',tz)` e próximo dia → `{start,end}`.
- **Uso:** `consultarDisponibilidade` → `timeZone = await getClinicTimezone(clinicId)` → `dow = getDayOfWeekInTimezone(date,timeZone)` → `blocks = getScheduleBlocksForDay(...,dow)` → `{start,end}=getDayRangeUtc(date,timeZone)` → `booked = bookedSlots(...,start,end)` → `computeFreeSlots(...,timeZone)` onde cada slot `08:00` local → `zonedTimeToUtc(date,slot,timeZone)` para overlap com `booked` UTC.
- **Exemplo:** `2026-08-04 08:00` em `America/Sao_Paulo` (UTC-3) → `11:00Z`; em `America/New_York` EDT (UTC-4) → `12:00Z`; diferença 1h provada em integração; `Pacific/Kiritimati` +14 → `19:00Z` dia anterior.
- **Calendar:** `src/components/calendar/utils/date-utils.ts` e `useCalendarEvents.ts` já expandem range `±1 dia` para timezone offset, mas ainda usam `date-fns` local; disponibilidade agora é autoridade para slots, calendar consome via `GET /api/appointments/availability` e `listarConsultas` com `start_date/end_date` UTC.
